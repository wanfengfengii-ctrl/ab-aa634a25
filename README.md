# 水声阵列接线复核台

水下声学阵列检修后，水听器通道可能被交叉换插或反接。本工具是一个 **纯前端**（TypeScript + React，全程不调用任何业务后端）的复核台：工程师在浏览器中录入或导入安装点侧与通道侧的逐点对观测数据，启动审计后得到完整裁决与最优见证。

## 问题定义与裁决语义

- 输入：`4 ≤ n ≤ 14` 个唯一安装点与等量采集通道；两侧**每个无序点对**的有向整数时延（以 `i → j` 方向录入，允许负整数）与正/负相关符号；非负时延容差。
- 合法解：安装点到通道的**双射**，并为每个通道选择**正/负极性**；按端点方向规范化后：
  - 每个点对的时延绝对误差 `|期望 − 实测| ≤ 容差`；
  - 每个点对满足 `安装点侧符号 = 通道侧符号 × 两端通道极性`。
- 唯一目标：全部点对时延绝对误差之和最小。
- 裁决完备四分类：**输入无效 / 无可行解 / 唯一最优 / 多解最优**；多解时给出按安装点编号顺序字典序最小的两份「映射＋极性」见证。
- 整体极性翻转物理上不可区分，裁决统一将首个安装点对应通道的极性规范化为 ＋。
- 页面逐对展示期望时延、实测时延、误差与符号核对；**修改任何输入都会作废旧裁决**。

求解器为字典序分支定界（容差/符号硬约束 + 两项下界剪枝），在 Web Worker 中精确求解，不阻塞页面。

## 本地开发

```bash
npm install
npm run dev      # 开发服务器
npm run test     # 求解器单元测试（vitest）
npm run build    # 类型检查 + 产物构建（dist/）
```

## Docker 运行（静态 Web，含健康检查）

```bash
docker compose build
WEB_PORT=8080 docker compose up web      # 宿主机端口可通过 WEB_PORT 配置，默认 8080
# 健康检查：http://localhost:8080/healthz
```

## 浏览器验收（一次性服务 verify）

`verify` 服务等待 `web` 健康后，在真实 Chromium 中执行验收（四类裁决、见证切换、逐对表格、导入导出、修改输入作废旧裁决等），随后自行退出并以退出码报告结果：

```bash
docker compose up --build --exit-code-from verify verify
echo $?        # 0 = 全部通过，1 = 存在失败
```

## 导入 JSON 格式

```json
{
  "points": ["P1", "P2", "P3", "P4"],
  "channels": ["C1", "C2", "C3", "C4"],
  "tolerance": 2,
  "pointPairs": [{ "i": 0, "j": 1, "delay": 12, "sign": 1 }],
  "channelPairs": [{ "i": 0, "j": 1, "delay": 12, "sign": 1 }]
}
```

- `pointPairs` / `channelPairs` 须恰好覆盖全部 `n(n-1)/2` 个无序点对各一次；`delay` 为整数（方向 `i → j`，若条目 `i > j` 则自动取负规范化），`sign` 为 `1` 或 `-1`。
- 页面「导出 JSON」按钮可生成同格式文件。
